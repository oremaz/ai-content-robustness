\paragraph{Probability-exposure pilot: a copying control}
\label{sec:exposure_control}
The interface candidate in Section~\ref{app:exposure} is first evaluated on 32 newly reserved HC3 questions. Each source answer is generated by the native TextSeal2 implementation. Four blind rewriting arms compare pre-watermark versus estimated key-conditional probability exposure, each with direct resampling or confidence-dependent reference smoothing. Every arm produces three attempts per source; all 384 attempts are saved before quality evaluation or owner scoring. The quality rule requires Jina similarity at least $0.9$, bidirectional NLI entailment without truncation, exact preservation of the extracted number set, finite reference perplexity at most $1.5$ times the original, and no empty, capped or degenerate output. The first passing attempt is selected without detector feedback.

The selected outputs preserve almost all source token-context pairs: mean descriptive four-token-pair overlap is $0.9927$, $0.9221$, $0.9636$ and $0.9930$ in table order. These overlaps use saved generation token IDs and are not calibrated hypothesis tests. Literal string equality would misleadingly report zero exact copies because punctuation and formatting change. The observed two versus zero removals under smoothing cannot establish a meaningful defense benefit when the baseline attack mostly copies marked text. A subsequent development pilot strengthens the paraphrasing instruction and forbids source four-token completions in both target and reference supports, with explicit accounting when no allowed probability mass remains. It retains the same quality gates. This iteration reuses the 32 sources, so it is development rather than independent confirmation.

\paragraph{Why a clean-oracle argument is insufficient here.} Even a pre-watermark model distribution is evaluated on a prompt containing the original marked answer. That answer depends on the secret key. Therefore the rewrite can preserve key information through its input, although the probability computation itself does not consult the key. An impossibility argument for key-independent prompts and a clean resampling oracle does not apply to this experiment without accounting for that dependence. Conversely, the exact-law identity for conditional exposure does not guarantee robustness under smoothing, truncation or substantive rewriting. Both distinctions are required when interpreting the next pilot.

\paragraph{Rewriting with source-pair blocking.}
The completed second pilot keeps all 32 marked source answers and the same quality gates. Its stronger instruction and source four-token blocking substantially change the attack. The blocking operates after mixing target and reference supports; if no mass remains, the unmasked response is used and the fallback is recorded. This is an explicit exception rather than a guarantee of zero copied source pairs. The native detector is applied only after all attempts and the first quality-passing selections are frozen.

This test shows a development benefit: valid removals decrease from 25 to 5 for direct resampling and from 22 to 12 for smoothing. Preservation passes change from 25 to 24 and from 22 to 27, respectively, so the lower joint removal is not explained solely by rejecting more conditional-interface outputs. Nevertheless, this is a single-key, 32-source development comparison with three attempts per arm. The source identities have already been used in the copying control. The fresh human-null diagnostic remains 0/32 at the native nominal threshold, which cannot precisely validate a $0.1\%$ false-positive rate. Independent prompts, additional keys, conditional-estimator checks and adaptive ratio attacks remain required.
